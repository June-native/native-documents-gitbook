# Error Handling

## Error Handling

Requests with application or business logic errors will return with an HTTP code of 200, but with additional fields for error code and message. For example:

```json
{
  "code": 171008,
  "message": "not found token info"
}

{
  "code": 171018,
  "message": "expire time exceeds global limit 60s"
}
```

To verify the response status, check whether `code` is present in the response. Successful quote responses also carry `success: true`, but not every endpoint returns a `success` field.

Codes that are not individually mapped are normalised by the gateway: any code starting with `3` or `4` is returned as `quote invalid, risk management checks failed`, and any other unmapped code is returned as `failed to provide quote, mm not available` together with the original code.

{% hint style="info" %}
Please note that for endpoints that typically return an array, gateway-level errors (for example an invalid `chain`) are returned in object format, for example /orderbook. If the orderbook backend times out (1s), `/orderbook` returns an empty array `[]` with HTTP 200.
{% endhint %}
